# Terraform AWS Infrastructure (Lesson 5)

## Опис проєкту

Цей проєкт автоматизує розгортання базової інфраструктури в AWS за допомогою Terraform. Інфраструктура побудована за модульною архітектурою з дотриманням сучасних практик безпеки (Security Best Practices) та архітектури AWS.

В рамках проєкту створюються такі ресурси:
- **S3 Bucket** для зберігання стану (state) Terraform.
- **DynamoDB Table** для блокування стану (State Locking) та запобігання конфліктам при паралельній роботі.
- **VPC з підмережами**, що включає публічні та приватні підмережі, Internet Gateway та NAT Gateway.
- **Amazon ECR Repository** для зберігання Docker-образів.

## Безпека та Best Practices

У цьому проєкті реалізовано наступні заходи безпеки:
- **Ізоляція мережі:** Приватні підмережі не мають публічних IP-адрес. Вихід в інтернет (наприклад, для завантаження оновлень) здійснюється безпечно через **NAT Gateway**.
- **Захист S3 Backend:** S3-бакет для стейту використовує шифрування на стороні сервера (**AES256**) та повністю закритий від публічного доступу.
- **Безпека ECR:** 
  - Увімкнено автоматичне сканування образів на вразливості.
  - Репозиторій зашифрований алгоритмом **AES256**.
  - Доступ обмежено лише для поточного AWS-акаунту через IAM Policy.
- **Оптимізація витрат (ECR Lifecycle):** Налаштовано політику життєвого циклу, яка автоматично видаляє старі образи, залишаючи лише 10 найновіших.
- **Управління секретами:** Усі змінні винесено з коду у файл `terraform.tfvars`, який додано до `.gitignore`, що унеможливлює випадковий витік даних.

## Підготовка до запуску

1. Переконайтеся, що у вас встановлено **Terraform** та **AWS CLI**.
2. Налаштуйте доступ до вашого AWS-акаунту.
3. Створіть файл зі змінними на основі прикладу:
```bash
cp terraform.tfvars.example terraform.tfvars
```
4. Відкрийте створений файл `terraform.tfvars` та за потреби змініть значення під свій проєкт (зокрема, s3_bucket_name має бути глобально унікальним).

## Команди для роботи

Ініціалізація проєкту (завантаження провайдерів та модулів):
```bash
terraform init
```

Перевірка плану виконання (що саме буде створено):
```bash
terraform plan
```

Розгортання інфраструктури:

```bash
terraform apply
```

Видалення інфраструктури:
```bash
terraform destroy
```

*⚠️ Увага: NAT Gateway є платним ресурсом в AWS. Обов'язково виконуйте terraform destroy після завершення тестування, щоб уникнути зайвих витрат.*

## Вихідні дані (Outputs)

Після успішного виконання `terraform apply` ви отримаєте наступні дані:
- `s3_bucket_name` — Назва S3-бакета зі стейтами.
- `dynamodb_table_name` — Назва таблиці DynamoDB.
- `vpc_id` — Ідентифікатор створеної VPC.
- `vpc_cidr_block` — CIDR блок мережі.
- `nat_gateway_ip` — Публічна IP-адреса NAT Gateway.
- `ecr_repository_url` — URL створеного ECR-репозиторію (використовується для docker push).
- `ecr_repository_arn` — ARN ECR-репозиторію.
